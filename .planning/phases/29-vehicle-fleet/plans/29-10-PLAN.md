1. Создать `vehicles_dashboard.py` с `router = APIRouter(prefix="/api/vehicles-dashboard", tags=["vehicles"])`.
2. Helper `_period_filter(date_field, date_from, date_to)` → SQLAlchemy where clause.
3. `_visibility_clause(user)` — копия из vehicles.py (vehicles.owner/assigned_org_id IN org_ids).
4. **KPI cards endpoint `GET /api/vehicles-dashboard/kpi?date_from=&date_to=&owner_org_ids=&region=`**:
   - `total_vehicles` — count(*) FROM vehicles WHERE visibility AND optional org filter
   - `fuel_total_cost` — SUM(total_amount) FROM fuel_logs WHERE date BETWEEN + visibility (через JOIN vehicle)
   - `repairs_total_cost` — SUM(cost_amount) FROM vehicle_repairs WHERE date BETWEEN + status='done' + visibility. **Альтернативно** при наличии linked Purchase брать `Purchase.contract_price` (D-18). Запрос:
     ```sql
     SELECT COALESCE(SUM(COALESCE(p.contract_price, vr.cost_amount, 0)), 0)
     FROM vehicle_repairs vr
     LEFT JOIN purchases p ON p.id = vr.purchase_id
     JOIN vehicles v ON v.id = vr.vehicle_id
     WHERE vr.date BETWEEN ... AND <visibility>
     ```
   - `total_mileage_km` — SUM of all per-vehicle delta. Implementation: для каждой машины `MAX(odometer_km) - MIN(odometer_km)` за период.
   - Возвращает `{total_vehicles, fuel_total_cost, repairs_total_cost, total_mileage_km}`.
5. **`GET /api/vehicles-dashboard/fuel-canister?date_from=&date_to=&fuel_budget=`** — for SVG canister widget:
   - `spent_l` — SUM(liters) FROM fuel_logs WHERE date BETWEEN + visibility
   - `spent_amount` — SUM(total_amount)
   - `fuel_budget` — берётся из query param (юзер задаёт сам) или default = 1.5 * spent_amount для прошлого периода. Если 0 — `level = 0.5` (показывать половину как нейтральное состояние).
   - `level` — float 0..1 = (fuel_budget - spent_amount) / fuel_budget (доля оставшегося бюджета). Если spent > budget → level=0.
   - Возвращает `{spent_l, spent_amount, fuel_budget, level, period_label}`.
6. **`GET /api/vehicles-dashboard/in-repair`** — list vehicles WHERE есть открытый VehicleRepair (status IN 'planned'/'in_progress'). visibility. Возвращает `[{vehicle_id, brand, model, plate, photo_attachment_id, repair_id, repair_status, repair_description, mileage_at_repair, expected_finish_date}]`. expected_finish_date — пока nullable, поле не было в плане, использовать NULL. photo_attachment_id — SELECT первый attachment с kind='photo'.
7. **`GET /api/vehicles-dashboard/maintenance-warning`** — список ТС где нужно внимание. Условия (любое):
   - `(next_to_km - current_odometer_km) < 1000`
   - `insurance_until < today + 30 days`
   - Водитель с просроченной ВУ (`license_expires_at < today` — JOIN users через trips за последние 30 дней)
   - Водитель с просроченной медсправкой
   - Возвращает `[{vehicle_id, brand, model, plate, warning_type ('TO_SOON'|'OSAGO_EXPIRY'|'LICENSE_EXPIRY'|'MED_CERT_EXPIRY'), days_left, km_left}]`. Сортировать по серьёзности (минимум days/km сверху).
8. **`GET /api/vehicles-dashboard/by-org?mode=owner|assigned`** — для bar chart. SELECT org_id, count(*) FROM vehicles GROUP BY org_id (либо owner_org_id, либо assigned_org_id). JOIN с organizations для name. Возвращает `[{org_id, org_name, count}]`.
9. **`GET /api/vehicles-dashboard/fuel-by-period?granularity=day|week|month|year&date_from=&date_to=`** — line chart данные. SUM(total_amount) FROM fuel_logs GROUP BY date_trunc(granularity, date). Возвращает `[{period, total_amount, total_liters}]`.
10. **`GET /api/vehicles-dashboard/state-donut`** — donut. SELECT state, count(*) FROM vehicles GROUP BY state. Возвращает `[{state, label, count, color}]`. color mapping: working=green, broken=red, in_repair=orange, needs_repair=yellow.
11. **`GET /api/vehicles-dashboard/top-expenses?limit=10&date_from=&date_to=`** — TOP-10. SELECT vehicle, SUM(fuel cost + repair cost). LEFT JOIN linked Purchase fall back на VehicleRepair.cost_amount / FuelLog.total_amount. ORDER BY total_cost DESC LIMIT 10. Возвращает `[{vehicle_id, plate, brand_model, fuel_cost, repair_cost, total_cost}]`.
12. Все endpoints — require_tab('vehicles') + visibility filter.
13. В `__init__.py` `include_router(vehicles_dashboard.router)`.

## Risks / Gotchas
- **Heavy aggregations:** для top-expenses и fuel-by-period — потенциально медленно. На 51 ТС не страшно, но добавить LIMIT и optional date filter (default last 90 days если не передано).
- **Visibility для агрегатов:** обязательно фильтровать ВСЕ запросы по `_visibility_clause`. Без этого employee увидит чужие машины.
- **Линковка purchase ↔ repair:** SUM логика должна не double-count'ить (если есть Purchase, не суммировать ещё и VehicleRepair.cost_amount). Использовать `COALESCE(p.contract_price, vr.cost_amount, 0)` — если есть Purchase, берём оттуда.
- **next_to_km / current_odometer_km могут быть NULL** — пропускать такие машины в TO_SOON фильтре (`WHERE next_to_km IS NOT NULL AND current_odometer_km IS NOT NULL`).
- **photo_attachment_id для in-repair:** subquery `SELECT id FROM vehicle_attachments WHERE vehicle_id=v.id AND kind='photo' LIMIT 1`.
