## Tasks
1. Создать `vehicle_odometer.py` с `router = APIRouter(prefix="/api/vehicle-odometer", tags=["vehicles"])`.
2. `_DATE_FIELDS = {"date"}`.
3. `_calc_delta_km(db, vehicle_id, date)` helper: SELECT max odometer_km для vehicle_id WHERE date < target_date. delta = current.odometer_km - prev_km (если prev_km IS NULL → delta=0, первая запись).
4. `_calc_fuel_used_l(delta_km, vehicle, odometer_date)` helper (per R-4):
   ```python
   def _calc_fuel_used_l(delta_km, vehicle, odometer_date):
       month = odometer_date.month
       is_summer = 5 <= month <= 9
       norm = vehicle.fuel_norm_summer if is_summer else vehicle.fuel_norm_winter
       if norm is None or norm <= 0 or delta_km <= 0:
           return 0.0
       return round(delta_km * norm / 100, 2)
   ```
5. `GET /api/vehicle-odometer?vehicle_id={id}&date_from=&date_to=&limit=100` — список записей. require_tab. ORDER BY `date DESC`. Возвращает items с computed `delta_km` и `fuel_used_l` (вычислять в Python после SELECT — для эффективности можно single SELECT с window function `LAG()` если нужна оптимизация в будущем). visibility через vehicle.
6. `POST /api/vehicle-odometer` — create entry. `require_action('vehicle.odometer.write')`. Body: `{vehicle_id, date, odometer_km, note, source}`. Проверить UNIQUE — если уже есть запись на эту дату, 409 `{code:'DUPLICATE_ODOMETER_DATE',...}`. Проверить monotonic: odometer_km должен быть ≥ предыдущего значения. Если нет → 422 `{code:'NON_MONOTONIC_ODOMETER', last_km: prev_km, attempted_km: new_km, message: 'Одометр не может уменьшаться'}`. После INSERT обновить `Vehicle.current_odometer_km = max(current, odometer_km)` для быстрых фильтров (D-08 указывает это поле как snapshot).
7. `PATCH /api/vehicle-odometer/{id}` — partial update (date, odometer_km, note). Тот же _coerce + UNIQUE/monotonic checks.
8. `DELETE /api/vehicle-odometer/{id}` — удаление. После delete пересчитать `Vehicle.current_odometer_km` как max(odometer_km) для оставшихся записей.
9. Создать `fuel_logs.py` с `router = APIRouter(prefix="/api/fuel-logs", tags=["vehicles"])`.
10. `GET /api/fuel-logs?vehicle_id={id}&date_from=&date_to=` — список заправок. require_tab + visibility. ORDER BY date DESC.
11. `POST /api/fuel-logs` — create. `require_action('vehicle.odometer.write')` (можно использовать тот же action или ввести `vehicle.fuel.write` — в D-05 НЕТ отдельного, используем существующий `vehicle.odometer.write`). Body: `{vehicle_id, date, liters, price_per_liter, total_amount, fuel_type, receipt_attachment_id, note}`. Если `total_amount` НЕ передан → вычислить `liters * price_per_liter`. Если передан, использовать переданный (для случая когда чек содержит округление). Возвращает FuelLogOut.
12. `PATCH /api/fuel-logs/{id}`, `DELETE /api/fuel-logs/{id}` — стандартные.
13. `GET /api/fuel-logs/latest-price/{vehicle_id}` — возвращает price_per_liter из последней записи для машины. Fallback: средняя цена за последние 30 дней по org. Возвращает `{price_per_liter: float, source: 'latest'|'org_avg'|'none'}`.
14. В `__init__.py` `include_router(vehicle_odometer.router)` и `include_router(fuel_logs.router)`.
15. Commit message: `feat(29-07): backend routers vehicle_odometer + fuel_logs — time-series + fuel norm calc`

## Risks / Gotchas
- **UNIQUE(vehicle_id, date)** уже есть на DB level (план 29-02). Если INSERT даст `UniqueViolation` от asyncpg, нужно поймать и вернуть 409 dict-detail.
- **monotonic check** на application level — DB UNIQUE на (vehicle_id, date) не защищает от попытки insert меньшего значения для другой даты. Реализовать в Python через `_get_prev_odometer`.
- **`current_odometer_km` snapshot:** обновлять ТОЛЬКО если новое значение > текущего snapshot. При delete — пересчитать MAX.
- **fuel_norm_summer / fuel_norm_winter могут быть NULL** — тогда fuel_used_l = 0, не падать.
- **Lesson 2026-05-13: `_coerce_patch_value`** для `date` Column.
- **dict-detail для всех ошибок** (Lesson 2026-05-04).
