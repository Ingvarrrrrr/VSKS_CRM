## API Reference

### Endpoints

| Method | Path | Status | Description |
|--------|------|--------|-------------|
| GET | `/api/purchases/{pid}/contract-items` | 200 | List all items ordered by id |
| POST | `/api/purchases/{pid}/contract-items` | 201 | Create single item + D-07 recalc |
| PUT | `/api/purchases/{pid}/contract-items` | 200 | Bulk replace (atomic) + D-07 recalc |
| PATCH | `/api/purchases/{pid}/contract-items/{item_id}` | 200 | Partial update + D-07 recalc |
| DELETE | `/api/purchases/{pid}/contract-items/{item_id}` | 204 | Delete + D-07 recalc |
| POST | `/api/purchases/{pid}/contract-items/copy-from-purchase` | 200 | 1:1 copy from purchase_items |

```json
  }

```

## Decisions Made

- **Catch-all ordering**: `contract_items_router` registered at line 505, `purchases.router` at 506 — guarantees `/api/purchases/{pid}/contract-items` is resolved correctly
- **No circular import**: `_recalc_contract_price_from_contract_items` defined in `purchases.py`, imported by `contract_items.py` (not the other way)
- **D-06 position**: Guard added AFTER TRANSITION_REQUIRED field guards, BEFORE `p.status = target_status` — field validation runs first, then contract_items check
- **copy-from-purchase overwrite semantics**: always delete+insert (not 409 if exists) — simpler UX when user wants to "refresh from request"
- **top-level ContractItem import** in `purchase_transitions.py`: per NameError prevention rule (Pitfall 4), not lazy inside function
