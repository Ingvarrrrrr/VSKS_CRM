## Cross-Phase Integration Issues

### 🔴 CRITICAL — Unauthenticated Publication Status Endpoint
`PATCH /api/publications/{id}/status` (`publications.py:603`) has **no `get_current_user` dependency**. Any HTTP client with a valid publication ID can set status to `published` with an arbitrary `external_url`. POST and GET on the same router both require auth; only PATCH is unprotected.  
**Fix:** Add `_: User = Depends(get_current_user)` (or a system-token check) to the PATCH handler.  
**Affects:** ROLES-06

### 🔴 HIGH — BUDGET-06 Not Enforced in Purchase Save
`_check_budget()` in `purchases.py` checks only subsidy budget — never fetches the linked contract's `max_amount`. `create_purchase` and `update_purchase` have no contract ceiling check. CONTRACT-06 90% warning in the purchase form also absent.  
**Affects:** BUDGET-06, CONTRACT-06

### 🟠 HIGH — ROLES-03 API Enforcement Incomplete
Frontend router guard correctly redirects employees to `/my-tasks`. But `GET /api/purchases/` and `PUT /api/purchases/{id}` use only `get_current_user` (not `require_role(*MANAGER_ROLES)`), returning HTTP 200 for authenticated employees — not 403 as ROLES-03 requires.  
**Affects:** ROLES-03, ROLES-06

### 🟠 HIGH — Phase 7 Viewer Dead End
ROLES-03 requires Viewer lands on 'Мои заявки'. WISHES-06 ('Мои заявки' view) is NOT built. An employee account has no valid landing page — the router guard redirects to `/my-tasks` which likely 404s or is the tasks view, not wishes.  
**Affects:** ROLES-03, WISHES-06

### 🟡 MEDIUM — PURCHASE-05 State Machine Out of Sync with Spec
Spec: `planned → confirmed → contracted → delivered → paid` (5 states).  
Actual `STATUS_ORDER`: `wishes → plan_schedule → confirmed → work_in_progress → contracted → delivered → paid` (7 states).  
Three undocumented states added. Requirements document not updated.  
**Affects:** PURCHASE-05

### 🟡 LOW — FILES-06 Delete Has No Role Restriction
`DELETE /api/purchases/{id}/files/{fid}` uses only `get_current_user` — no `require_role` check. Any authenticated employee can delete purchase files via direct API.  
**Affects:** FILES-06

### 🟡 LOW — Phase 8 Architecture Drift
GSD plans 08-01/02 document n8n as the integration middleware. Production since `265c68e` uses direct API calls. `n8n_workflows/roseltorg_publish.json` and `fabrikant_publish.json` in repo are dead artifacts. Documentation and code are misaligned.  
**Affects:** PUB-01..10 (informational)
