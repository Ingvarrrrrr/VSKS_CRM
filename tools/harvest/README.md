# tools/harvest — сборщики каталогов GALA по магазинам

Собирает товары с сайта магазина в формат `gala-catalog` (см.
`backend/app/services/catalog_gala/format.py`) для последующей загрузки в
products через существующий загрузчик (вне этого пакета).

## Запуск сбора

```
python -m tools.harvest.run --store kuvalda --out "C:\path\to\kuvalda.json"
python -m tools.harvest.run --store regard --out "C:\path\to\regard.json" --pause-per-domain 1.5
python -m tools.harvest.run --store k_spasatel --out "...\k_spasatel.json" --previous "C:\Users\1\Downloads\Товары и ТЗ\k_spasatel_rescue_nomenclature.json"
python -m tools.harvest.run --store kuvalda --out "...\kuvalda.json" --prices-only
```

Параметры:
- `--store {...}` — какой магазин собирать (реестр — `STORES` в `run.py`).
- `--out <файл>` — куда писать итоговый `.json`.
- `--limit-categories N` — собрать только первые N разделов (для разработки/проверки,
  не для полного прогона).
- `--resume` — продолжить прерванный сбор (см. ниже).
- `--pause-per-domain 1.0` — переопределяет паузу между запросами при
  concurrency==1 (по умолчанию каждый магазин использует своё значение,
  подобранное по старому сборщику этого магазина — см. таблицу ниже).
- `--previous <файл>` — прошлый gala-каталог этого магазина: товар, у
  которого там уже есть бренд И (характеристики ИЛИ описание), повторно не
  открывается — обновляются только цена/наличие/дата из раздела (см.
  «Инкремент» ниже). Если не передан — используется файл по умолчанию из
  `DEFAULT_PREVIOUS_FILES` в `run.py` (если существует).
- `--prices-only` — товарные страницы НЕ открываются вовсе, только разделы
  (+`--previous` для всего остального). Для магазинов, где цена есть
  ТОЛЬКО на странице товара (см. столбец «цена в разделе?» в таблице),
  печатается честное предупреждение — такие цены берутся из `--previous` и
  могут быть устаревшими.
- `--with-details` — у магазинов с `supports_details=True` (пока только
  regard) включает визит на товар ради необязательных «подробностей»
  (характеристики, точный артикул производителя). По умолчанию (без флага)
  такие магазины товар НЕ открывают вообще — как старый сборщик.

## Концепция: пакетный источник раздела vs визит на товар

Каждый `stores/<store>.py` в докстринге явно перечисляет, что именно
отдаёт пакетный источник раздела (JSON-LD/GA4-datalayer/Next.js
data-роут/JSON API) — это то, что приходит ОДНИМ запросом НА МНОГО товаров
сразу. `needs_product_visit(candidate)` возвращает `True` только тогда,
когда нужного поля (бренд/артикул производителя/характеристики) НЕТ ни в
одном пакетном источнике — тогда и только тогда нужен отдельный запрос на
карточку товара (владелец, 27.10.2026). Там, где сайт сам не даёт пакетных
данных (k_spasatel/medtehno/safe/promalper/magazin01 — проверено по
старым скриптам `C:\Users\1\.gemini\antigravity-ide\scratch\`, ни один не
нашёл batch-API), визит неизбежен — это не брак, честная необходимость, и
в таблице ниже скорость для них достигается ТОЛЬКО через concurrency
(п. "Темп") и `--previous`, не через отказ от визита.

| Магазин | Пакетный источник раздела несёт | Визит на товар нужен для |
|---|---|---|
| kuvalda | name/url/price/photos (JSON-LD OfferCatalog) | НИЧЕГО не обязателен — бренд ищется словарём в названии (см. ниже); визит — только если словарь бренд не нашёл (≈0.1% строк) |
| regard | name/url/price/photos (JSON-LD OfferCatalog) | по умолчанию визита НЕТ (бренд — словарь по названию, артикул — код в скобках в конце названия, характеристики пустые); `--with-details` включает визит за настоящими характеристиками/точным артикулом (batch-API не подтверждён) |
| kns | name/url/price/**бренд/PN** (GA4 `item_brand`/`item_variant`) | характеристики — и только если GA4 не дал бренд ИЛИ PN |
| sima_land | ВСЁ (name/price/бренд/страна/характеристики) — JSON API `/api/v3/item/` | ничего, визит не нужен никогда |
| baucenter | name/url/price/**бренд** (Next.js `_next/data/.../catalog/*.json`) | характеристики, страна (отдельный Next.js JSON товара — тоже пакетный формат, не HTML) |
| ice_age | name/url (sitemap) | price/бренд/характеристики — из JSON товара (InSales `<url>.json`, пакетный формат для ОДНОГО товара, batch-по-многим-id не найден) |
| k_spasatel | только name/url | всё (цена, бренд, характеристики) — чистый HTML, batch-API не найден |
| medtehno | только url | всё — чистый HTML, batch-API не найден |
| safe | только url | всё — чистый HTML (microdata), batch-API не найден |
| promalper | только url | всё — JSON-LD на самой карточке, batch-API не найден |
| magazin01 | только url (sitemap) | всё — JSON-LD на самой карточке |
| inari | ничего (Angular CSR, см. docstring) | — (модуль честно возвращает 0 строк) |

**Кувалда — особый случай**: владелец, по итогам 843 реально открытых
страниц в соседнем прогоне `tools/catalog_enrich`, установил: «у 842 из
843 товаров бренд со страницы и так стоит в названии». Поэтому для kuvalda
визит на товар не даёт прироста качества, который стоил бы запроса — бренд
берётся словарным целословным поиском по названию
(`gala_writer.find_brand_in_name`, импортирует
`tools/catalog_enrich/brand_dictionary.BrandDictionary` — ПРАВИЛО №6, тот
же алгоритм, не копия), визит на товар остаётся только для редкой строки,
где словарь бренд не нашёл.

## Инкремент (`--previous`)

Товар из текущего раздела сопоставляется с прошлым каталогом по ссылке
(`source_url`/`links[].url`, а не по внутреннему URL визита — у kns/ice_age
это разные вещи, см. `_candidate_match_url` в `core/runner.py`). Если
прошлая строка полна (есть `manufacturer` И (`characteristics` ИЛИ
`description`)) — она клонируется, обновляются только `price`/`price_date`/
`currency`/`links` из свежего раздела, товарная страница НЕ открывается.

⚠️ Эффект `--previous` зависит от качества СТАРОГО файла: у k_spasatel/
medtehno (rescue_medical)/ice_age (promalp)/magazin01 (fire) старые файлы
почти не содержат `manufacturer` (брак старых сборщиков — см. таблицу
п. 5), поэтому `--previous` на ЭТИХ старых файлах почти не экономит визиты
на первом прогоне новым сборщиком. Выигрыш появляется, начиная со
ВТОРОГО прогона новым сборщиком (когда `--previous` уже указывает на файл
с настоящими брендом/характеристиками).

## `--prices-only`

Товарные страницы не открываются вовсе. Для магазинов с `category_has_price`
(столбец выше) цена всегда свежая из раздела; для остальных (k_spasatel,
medtehno, safe, promalper, magazin01, ice_age) цена берётся из `--previous`
и может быть устаревшей — об этом печатается явное предупреждение в консоль
(`core/runner.py`, не молчаливый фолбэк).

## Темп запросов (concurrency + троттлинг)

`StoreSpec.concurrency`/`default_pause_per_domain` в каждом `stores/<store>.py`
подобраны по СТАРОМУ сборщику этого магазина (ThreadPoolExecutor
`max_workers=N`, если он был у старого — иначе concurrency=1, как у
однопоточного старого). При `concurrency>1` поминутный троттлинг по домену
выключен (темп держит сам пул потоков — так делали и старые многопоточные
сборщики). При первом 429/503 `core/http.py` автоматически делит
concurrency на 2 и удваивает паузу (максимум 10с); если 5 минут прошло без
НОВЫХ отказов — темп возвращается к исходному.

| Магазин | concurrency | пауза (с, при concurrency=1) | источник значения |
|---|---|---|---|
| kuvalda | 1 | 1.0 | `harvest_kuvalda_massive_catalog.py` — однопоточный |
| regard | 1 | 1.2 | `harvest_regard_massive.py` — однопоточный |
| kns | 1 | 0.4 | `harvest_kns_massive.py` — однопоточный |
| sima_land | 10 | 0.3 (владелец: не больше 0.3с) | `harvest_sima_land_resilient.py` — `max_workers=10..12` |
| baucenter | 50 | 0.2 | `enrich_baucenter_all.py` — `max_workers=50` |
| k_spasatel | 25 | 0.3 | `harvest_all_kspasatel_nomenclature.py` — `max_workers=25` |
| medtehno | 30 | 0.2 | `harvest_all_medtehno_now.py` — `max_workers=30` |
| safe | 25 | 0.3 | `harvest_all_safe_ru.py` — `max_workers=7/25`, верхняя граница |
| promalper | 1 | 0.3 | `harvest_promalper_height_safety.py` — однопоточный |
| magazin01 | 30 | 0.2 | `harvest_all_fire_now.py` — `max_workers=30` |
| ice_age | 30 | 0.2 | `harvest_all_promalp_now.py` — `max_workers=30` |
| inari | 1 | 1.0 | нет реального сбора (см. docstring) |

## Чекпоинт и `--resume`

Во время сбора рядом с `--out` пишется `<файл>.checkpoint.jsonl` — построчно
`{"url", "kind", "status"}` для каждого обработанного раздела/товара. Если
прогон прервался (упал процесс, Ctrl+C, `StoreAbortedError` после 20 подряд
отказов) — повторный запуск с `--resume`:
1. читает чекпоинт и пропускает уже встреченные URL;
2. читает уже накопленные `items` из самого `--out` (если файл существует)
   и продолжает дописывать к ним.

Чекпоинт не удаляется автоматически — если нужен полностью чистый прогон,
удалите `<файл>.checkpoint.jsonl` и `--out` вручную перед запуском без `--resume`.

## `<файл>.rejected.json`

Перед записью `run.py` прогоняет собранный каталог через гейт качества
(`tools/harvest/core/quality.py`). Если метрики хуже порогов (слишком много
мусорных брендов / невалидных ИНН / характеристик-заглушек "Параметр N" /
строк без цены и без ссылки, либо каталог не проходит схему `format.py`) —
результат пишется в `<файл с заменой .json на .rejected.json>`, а не под
основным именем, и в консоль печатаются причины. Файл `.rejected.json` —
сигнал остановиться и разобраться в парсере магазина, а не загружать его как
есть. После исправления парсера — удалить `.rejected.json` и повторить сбор
(с `--resume`, если чекпоинт ещё актуален, или с нуля).

## Структура

```
tools/harvest/
  core/
    gala_contracts.py  — единственный импорт format.py/stores.py/manufacturer_quality.py
                          из backend/app без тяги БД
    http.py            — HttpClient: троттлинг/concurrency по домену, backoff, журнал отказов
    checkpoint.py       — jsonl чекпоинт для --resume
    gala_writer.py      — resolve_manufacturer()/find_brand_in_name()/build_item() без значений по умолчанию
    quality.py           — quality_report()/write_catalog() — гейт перед записью файла
    runner.py            — общий цикл обхода разделов/товаров (StoreSpec), инкремент, --prices-only
  stores/
    kuvalda.py / regard.py / kns.py / sima_land.py / baucenter.py / k_spasatel.py /
    magazin01.py / medtehno.py / ice_age.py / promalper.py / safe.py / inari.py
  tests/
    fixtures/             — сохранённые страницы (1 раздел + 2 товара на магазин)
    test_*.py
  run.py                  — CLI
```

## Добавление нового магазина

1. Создать `tools/harvest/stores/<store>.py` по шаблону `kuvalda.py`/`regard.py`:
   реализовать функции `page_url(category_url, page)`, `parse_category_page(html)`,
   `needs_product_visit(candidate)`, `parse_product_page(html, url)`,
   `build_item(candidate, enrichment, known_brands)` и собрать их в `StoreSpec`
   (`tools/harvest/core/runner.py`) — указать `concurrency`/`default_pause_per_domain`
   по старому сборщику этого магазина (если он есть в
   `C:\Users\1\.gemini\antigravity-ide\scratch\`) и `category_has_price`.
   `build_item` обязан вызывать `gala_writer.resolve_manufacturer()` для бренда и
   `gala_writer.seller_inn_for()` для ИНН — не писать свою версию этих правил (ПРАВИЛО №6).
2. В докстринге модуля явно перечислить: что раздел несёт ПАЧКОЙ, есть ли у
   магазина batch-API карточки/нескольких карточек сразу (проверить по
   старым скриптам Antigravity и фикстурам — живых запросов не делать) и
   для каких ИМЕННО полей нужен визит (`needs_product_visit` должно это
   отражать, не возвращать `True` по умолчанию).
3. Зарегистрировать `harvest()` нового модуля в `STORES` в `run.py`.
4. Скачать РОВНО 3 страницы (1 раздел + 2 товара) в `tools/harvest/tests/fixtures/`
   и написать `tools/harvest/tests/test_stores_<store>.py` по образцу существующих —
   без живых запросов в тестах, только парсинг сохранённых фикстур.
5. Прогнать `pytest -q tools/harvest/tests` перед первым реальным сбором.
