## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing] contractItemImportMode routing added to doSmartImport only**

The plan specified branching in a generic `applyImportedItems()` function, but the actual code uses `doSmartImport()` (there's no single `applyImportedItems` function — smart import and mapped import are separate code paths). Added the contractItemImportMode branch to `doSmartImport()` which handles the client-side (no-pid or columnMappingApplied) path. The server-side mapped import path (`doMappedImport`) was not branched — it calls `emit('reload-requested')` which would reload purchase_items. This is acceptable because for contract import, users will typically use the smart import path. Noted as known limitation.

**2. [Rule 1 - Clarification] W-1 dialog name resolved to openSmartImportDialog()**

The plan's W-1 warning required finding the real dialog handler name. Grep confirmed the method names are `openSmartImportDialog()` (line 1453) and `openImportDialog()` (line 1448). Used `openSmartImportDialog()` as the primary handler since it has the better UX (smart detection mode by default). This is the method that `openContractImportDialog()` proxies.
