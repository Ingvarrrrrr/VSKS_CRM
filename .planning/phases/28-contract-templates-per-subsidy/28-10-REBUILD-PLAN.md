## Различия министерств сводятся к переменным (проверено диффом)

ФАДМ vs Минпрос vs Минтруд, «большая» и «малая»: **структурных расхождений нет**, отличаются только

1. `subsidy_grantor_name` — Росмолодежь / Минпрос / Минтруд (п. 1.3, 4.5, 4.6, преамбула Методики)
2. `subsidy_agreement_number` + `subsidy_agreement_date` (091-10-2025-032 / 073-10-2025-088 / 149-10-2025-043)
3. п. 4.1.1 — формулировка зависит от НДС (`возникнет НДС` vs `изменится ставка`), не от министерства
4. Банковские реквизиты ВСКС (Минтруд: лицевой 41736К02320, казначейский 03216643000000017300) — уже переменные
5. п. 8.1 — срок действия: до даты / до полного исполнения → `{% if %}`
6. Почтовый адрес — переменная

→ решение «один комплект с ветвлениями» подтверждено фактами.

## Архитектура сборщика

Новый **отслеживаемый** пакет `backend/templates/build/` (корневые одноразовые скрипты удаляются):

```
backend/templates/build/
  __init__.py
  sources.py     # doc_type -> путь к образцу
  docxedit.py    # движок правки XML
  rules_common.py# правила для всех 8
  rules/         # rules_services.py, rules_goods.py, rules_gph.py, rules_repair.py
  build.py       # CLI: python -m app.templates.build.build [--only doc_type] [--check]
```

**Движок `docxedit.py` — как избежать бага склейки runs:**

1. **Нормализация до правок**: принять tracked changes (`<w:ins>` разворачивается, `<w:del>` удаляется),
   выкинуть `<w:proofErr>`, `<w:bookmarkStart/End>`, `<w:lang>`-разбиение. Это корневая причина
   «мусорных» границ runs в старом скрипте.
2. **Замена по смещениям, а не regex поверх склеенного текста**: для каждого `<w:p>` собрать
   `text` + карту offset→(`<w:t>` node, позиция). Правило возвращает `(start, end, replacement)`.
   Замена вписывается в первый перекрытый `<w:t>` (формат сохраняется), остаток перекрытия обнуляется.
   Значение физически не может уехать в другой слот.
3. **Блочные условия** — отдельными абзацами `{%p if … %}` / `{%p endif %}` вокруг целевых `<w:p>`,
   не inline. Табличные циклы — `{%tr for item in items %}`.
4. **Идемпотентность**: сборка всегда из образца в чистый файл; повторный запуск даёт тот же результат.
   `--check` пересобирает во временную папку и диффит с закоммиченным.

### Методика приёмки — важно

Проверки «сколько бланков / сколько подстановок» **не годятся**: они зелёные при испорченном тексте.
Дважды дали ложный PASS. Обязателен строгий чекер `.tmp_p28_strict.py`:
рендер 8 шаблонов × 6 комбинаций с уникальными маркерами-сентинелами вместо значений
(иначе корректная подстановка неотличима от статики) и поиск реальной порчи —
литералы `\g<N>`, пустые `«»` и `()`, `№` без значения, двойные предлоги, остатки Jinja.
Сентинелы не должны содержать `<`, `>`, `&`: docxtpl не экранирует, документ рендерится пустым.

Текущее состояние: `total_fail=0`. Логика чекера перенесена в отслеживаемый
`backend/tests/test_contract_templates.py` (48 кейсов = 8 шаблонов × 6 комбинаций,
параметризация даёт падение на конкретной паре, а не одну общую цифру).
Тест бьёт по **установленным боевым** `backend/templates/contract_*.docx`, но строго
по списку из 8 doc_type: легаси `contract_fadm.docx` и `contract_template_source.docx`
захватывать нельзя — они мёртвые (в рантайме не используются) и заведомо сломаны
(`contract_fadm` падает `TemplateSyntaxError`: незакрытый `{% if %}`).
