# VSKS_CRM

## What This Is

CRM-система для управления закупками организации «ВСKS» — учёт субсидий, закупок, контрагентов, договоров и платежей. Система автоматизирует процесс от планирования закупки до её оплаты, контролирует бюджет по статьям ФЭО и формирует аналитику. Предназначена для менеджеров и руководителей учреждения.

## Core Value

Бюджетный контроль: не допустить превышения лимита субсидии при создании закупки — это главная защита от финансовых нарушений.

## Requirements

### Validated

- ✓ Аутентификация (JWT, 3 роли: admin/manager/viewer) — существует
- ✓ CRUD: субсидии, закупки, контрагенты, договоры, платежи, категории ФЭО — существует
- ✓ Дашборд с ApexCharts (KPI, donut, radial, pie, bar) — существует
- ✓ Фильтрация дашборда по году и субсидии — существует
- ✓ Карточный UI субсидий (SubsidiesView) — существует
- ✓ Данные ФАДМ_2026 загружены (390 закупок, 612 контрагентов) — существует

### Active

- [ ] Форма закупки с расширенными полями (20+ новых полей)
- [ ] Workflow статусов закупки (planned→confirmed→contracted→delivered→paid)
- [ ] Каскадные выпадающие ФЭО (3 уровня, зависимые)
- [ ] Проверка бюджета при создании/изменении закупки (блокировка при превышении)
- [ ] Загрузка файлов к закупке (таблица purchase_files уже есть в БД)
- [ ] Реестр договоров (типы: one-time/framework-unlimited/framework-limited)
- [ ] Экспорт в Excel (формат GoodsService)
- [ ] Импорт оплат из CSV/Excel (лист Scroller)
- [ ] История изменений бюджета (budget_history уже есть в БД)
- [ ] Страница «Желания» (Wishes) — сотрудник создаёт заявку
- [ ] Ролевая навигация (Admin/Manager/Viewer разные меню)
- [ ] Добавление категорий ФЭО через UI (кнопка есть, функционал не реализован)

### Out of Scope

- OCR PDF-документов — отложено (потребует pytesseract/внешнего API)
- Генерация DOCX из шаблонов — заглушка, шаблоны предоставит заказчик позже
- Мобильное приложение — не предусмотрено
- Интеграция с ЕИС (zakupki.gov.ru) — не в текущей версии

## Context

- Стек: Vue 3 + Vuetify 3 + TypeScript + Vite + ApexCharts (frontend); FastAPI + SQLAlchemy async 2.0 + PostgreSQL 15 (backend); Docker Compose 5 сервисов; n8n для автоматизации
- Данные реальные: дамп ФАДМ_2026, 390 закупок, все с subsidy_id=7, feo_category_id=NULL
- БД содержит таблицы purchase_files, budget_history, wishes — они уже созданы, нужно только подключить
- Все закупки ФАДМ_2026 на сумму 36,810,006₽ при лимите субсидии 15,500,000₽ (превышение — исторические данные)
- Переписка с заказчиком (Игорь Цыганов, 16.02–03.03.2026) задокументирована в vsks_crm_plan.md

## Constraints

- **Tech Stack**: Vue 3 + FastAPI + PostgreSQL — менять не планируется
- **Data**: PostgreSQL bytea для файлов (уже используется в дампе)
- **Roles**: Admin/Manager/Viewer — роли заданы, логика доступа фиксирована
- **Budget Check**: блокировка при превышении лимита субсидии — критичное требование
- **Backward Compat**: нельзя ломать существующие API — данные ФАДМ_2026 должны оставаться корректными

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| PostgreSQL bytea для файлов | Уже используется в дампе, не нужен S3/MinIO | Утверждено |
| Статусы workflow однонаправленные | Откат только через admin | Утверждено |
| Каскадные ФЭО в форме (3 уровня) | Иерархия категорий задана структурой таблицы | Утверждено |
| Блокировка при превышении бюджета | С возможностью override для admin | Утверждено |
| python-docx + Jinja2 для генерации DOCX | Шаблоны будут предоставлены позже | Отложено |
| openpyxl для экспорта/импорта Excel | Соответствие формату GoodsService | Утверждено |
