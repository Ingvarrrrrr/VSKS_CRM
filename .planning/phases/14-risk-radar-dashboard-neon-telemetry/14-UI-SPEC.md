## Spacing Scale

Standard 8-point grid. All spacing in multiples of 4px.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon internal gap, badge padding |
| sm | 8px | Between label and value in metric cells |
| 2xs | 12px | Card border-radius, `.rr-metric-grid` gap |
| md | 16px | Card internal padding (compact telemetry cards) |
| lg | 24px | Between panel groups, section separators |
| xl | 32px | Page edge padding (matches DashboardView: 20px 24px → use 20px top, 24px sides) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Radar chart container: 280px × 280px fixed (square, centered in its grid cell)
- Risk metric cards: 160px min-height, 12px border-radius (`2xs` token — matches existing `.kpi-card`)
- Ticker banner height: 36px fixed
- Touch target for toggle chip: 44px height (accessibility minimum)

## Typography

Inherits font-family from Vuetify (Inter / system-ui). No custom font loading.

**Maximum 4 sizes, 2 weights.**

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 26px | 700 | 1.2 | View title "Risk Radar" (matches `.dash-title` in DashboardView) |
| Heading | 20px | 700 | 1.2 | Risk score number inside each metric card |
| Body | 14px | 400 | 1.5 | Card label text, tooltip body, ticker items |
| Label | 12px | 400 | 1.4 | Section titles on telemetry panels, badge counts, sub-labels, percent values, timestamps ("last refreshed") |

**Label visual differentiation:** Section/panel titles that need to stand apart from body text use `letter-spacing: 0.06em; text-transform: uppercase;` at `font-weight: 400` — no additional weight is added. Timestamps, percent values, and sub-labels use `font-weight: 400; color: var(--crm-text-muted);` (reduced opacity via muted token) to differentiate visually from section labels without introducing a new weight or size.

Rules:
- Risk score numbers use `useAnimatedNumber` (easeOutExpo) — never static on first render
- Critical values (score ≥ 75) render in `--rr-critical` color, not default text color
- "Risk Radar" title uses the same `.gradient-text` animation as classic Dashboard title

- **60% dominant** — `--crm-bg` (page background + dot-grid layer, same as classic Dashboard)

- **10% accent** — neon severity tokens, reserved for: risk score numbers, card left-border accent strip, radar axis lines, severity badge text, animated glow on hover/critical pulse

Accent NOT applied to: body text, icons in neutral state, chart grid lines, header title (gradient-text instead)

## Risk Metrics Specification

Six risk dimensions. Each produces a score 0–100.

| # | Metric | Icon | Formula | Data Source |
|---|--------|------|---------|-------------|
| 1 | **Budget Overrun** | `mdi-cash-remove` | `sum(max(0, planned - budget)) / sum(budget) * 100` capped at 100 | `/api/dashboard/charts` → subsidy breakdown |
| 2 | **Contract Delays** | `mdi-file-clock` | `count(contracts where end_date < today + 14 days AND status != completed) / total_contracts * 100` | `/api/contracts` |
| 3 | **Stalled Wishes** | `mdi-star-remove` | `count(wishes WHERE status='approved' AND age > 14 days) / total_approved_wishes * 100` | `/api/wishes` |
| 4 | **Framework Saturation** | `mdi-chart-bell-curve` | `max(current_amount / max_amount * 100)` across all framework-limited contracts — worst case | `/api/contracts?type=framework-limited` |
| 5 | **FEO Imbalance** | `mdi-scale-unbalanced` | `std_dev(feo_utilization%) / mean(feo_utilization%) * 100` normalized to 100 — coefficient of variation | `/api/dashboard/charts` → FEO breakdown |
| 6 | **Overdue Payments** | `mdi-credit-card-remove` | `count(purchases WHERE status=contracted AND contracted_date < today - 30) / total_contracted * 100` | `/api/purchases` filtered |

### Overall Risk Score

`overall = weighted_average([score1*0.25, score2*0.20, score3*0.15, score4*0.20, score5*0.10, score6*0.10])`

Displayed as radialBar gauge (0–100) below the polar chart.

### Severity Thresholds

| Score | Severity | Color Token | Behavior |
|-------|----------|-------------|----------|
| 0–39 | OK | `--rr-ok` | No animation |
| 40–64 | WARN | `--rr-warn` | Subtle pulse (2s ease-in-out, 1 repeat) on first render |
| 65–79 | HIGH | `--rr-high` | Continuous glow animation (3s cycle) |
| 80–100 | CRITICAL | `--rr-critical` | Continuous pulse + toast notification via `useToast` |

## State Patterns

### Loading State

- Show `v-skeleton-loader type="card"` for each of the 6 metric cards (same pattern as DashboardView KPI loading)
- Polar chart area: solid `--rr-panel-bg` with centered `v-progress-circular` (32px, color = `--rr-ok`)
- Ticker: shimmer strip (width 100%, height 36px, animated background-position gradient)
- Duration: matches API response — typically 300–800ms

### Empty State (no data for selected filters)

**Heading:** Нет данных для анализа рисков

**Body:** Выберите субсидию и год, чтобы увидеть оценку рисков.

**Visual:** Polar chart placeholder showing 6 equal slices in `--crm-border` color (greyed out). Score gauge shows 0. No ticker.

### Error State

**Heading:** Не удалось загрузить данные

**Body:** Проверьте соединение и попробуйте снова. Нажмите ⟳ для повторной загрузки.

**Visual:** Red outlined `v-alert` with `mdi-alert-circle-outline` icon, placed where cards would be. No partial rendering.

### Hover State (metric cards)

- `transform: translateY(-3px)` — matches DashboardView `.kpi-card:hover`
- Box-shadow: `0 12px 28px var(--rr-glow-{severity})`
- Border color: `--rr-{severity}` (full opacity, from faded default)
- Cursor: `pointer` — indicates drill-down is available
- Transition: `0.25s cubic-bezier(0.22, 1, 0.36, 1)` (matches existing project animation)

### Active/Pressed State

- `transform: translateY(-1px) scale(0.98)` — matches DashboardView `.kpi-card:active`
- Transition-duration: 0.1s

### Critical State (persistent, not just on hover)

Applied to any card with score ≥ 80:

```css
@keyframes rr-critical-pulse {
  0%, 100% { box-shadow: 0 0 0 0 var(--rr-glow-critical); }
  50%       { box-shadow: 0 0 24px 4px var(--rr-glow-critical); }
}
.rr-metric-card--critical {
  animation: rr-critical-pulse 3s ease-in-out infinite;
  border-color: var(--rr-critical);
}
```

One toast fired via `useToast` on initial load if any score ≥ 80. Message: "Обнаружены критические риски: {metric names}" — `type: 'error'`, duration: 6000ms. Do NOT re-fire on manual refresh.

## Animation Specifications

### Permitted Animations

| Animation | Element | Spec | Rationale |
|-----------|---------|------|-----------|
| Score count-up | Risk score numbers | `useAnimatedNumber` easeOutExpo, 800ms | Visual confirmation data loaded |
| Card entrance | All 6 metric cards | `card-entrance` stagger 0.05s per card, 0.4s duration — same keyframes as DashboardView | Consistency with existing design |
| Polar chart load | ApexChart | ApexCharts built-in `animations.easing: 'easeinout'`, `animations.speed: 600` | Chart identity |
| Critical pulse | Critical-severity cards only | 3s ease-in-out infinite glow | Attention signal — data first |
| Ticker scroll | AlertsTicker | CSS `animation: ticker-scroll linear infinite`, speed 30s for full cycle | Ambient awareness |
| Dot-grid background | `.risk-radar::before` | Same as DashboardView (fixed, opacity 0.4, `--crm-border-strong` dots, 24px grid) | Visual continuity |

### Prohibited Animations

- NO rotating radar sweep animation — not supported in ApexCharts without heavy custom SVG overlay; data readability takes priority
- NO scan-line overlay — too decorative, interferes with readability in light theme
- NO shimmer/glitch effects
- NO entrance animations on the polar chart container itself — the chart's built-in animation suffices

### Easing Standard

All transitions use `cubic-bezier(0.22, 1, 0.36, 1)` (ease-out spring) — matches DashboardView established standard.

## Interaction Contracts

### Toggle: Classic Dashboard ↔ Risk Radar

**Placement:** In RiskRadarView.vue header only, right side — `v-chip-group` with two chips placed AFTER the refresh button.

```html
<v-chip-group v-model="dashboardMode" mandatory class="ml-3" selected-class="text-primary">
  <v-chip value="classic" size="small" variant="outlined" prepend-icon="mdi-view-dashboard">
    Классик
  </v-chip>
  <v-chip value="radar" size="small" variant="outlined" prepend-icon="mdi-radar">
    Радар
  </v-chip>
</v-chip-group>
```

**Behavior:**
- Selecting "Классик" → `router.push('/dashboard')`
- Selecting "Радар" → `router.push('/dashboard/radar')`
- Mode persisted in localStorage key: `dashboard-mode-{userId}` where userId from `localStorage.getItem('user_id')`
- `useDashboardMode.ts` composable reads this key on mount, redirects to correct route

**Implementation note:** DashboardView.vue is NOT modified in Phase 14. The toggle chip group is added only to RiskRadarView.vue header. A user on `/dashboard` (classic) reaches `/dashboard/radar` via browser navigation or a direct link — adding the toggle to DashboardView is deferred to Phase 14.1.

**Route strategy:** `/dashboard/radar` — new named route `radar-dashboard`, lazy-loaded, same access guard as `/dashboard` (no employee access).

### Metric Card Click → Drill-Down

Each of the 6 risk cards is clickable. On click:

| Card | Drill-Down Action |
|------|-----------------|
| Budget Overrun | Open `BudgetDrillDownDialog` (reuse existing, pass `subsidyId = null` for all) |
| Contract Delays | `router.push('/contracts?filter=expiring')` — navigate to ContractsView with filter |
| Stalled Wishes | `router.push('/wishes?filter=stalled')` — navigate to WishesView with filter |
| Framework Saturation | `router.push('/contracts?filter=saturated')` — navigate to ContractsView |
| FEO Imbalance | Open `BudgetDrillDownDialog` (FEO drill-down mode, already supports it) |
| Overdue Payments | `router.push('/orders?filter=overdue_payment')` — navigate to OrdersView |

Drill-down navigation is Phase 14 MVP scope. Filter params on destination views are pass-through — if the destination view ignores the query param, that is acceptable for MVP (the deferred drill-down from CONTEXT.md deferred section).

### Hover Tooltip

On hover over any metric card, show `v-tooltip` (location: top) with:

```
{MetricName}: {score}/100
{N} элементов требуют внимания
```

Example: "Бюджет: 73/100 · 3 субсидии с превышением"

Tooltip uses Vuetify default tooltip styling — no custom neon treatment.

### Polar Chart Slice Hover

ApexCharts built-in tooltip enabled. Custom formatter:

```typescript
tooltip: {
  y: {
    formatter: (val: number, opts: any) => {
      const label = opts.w.globals.labels[opts.seriesIndex]
      return `${label}: ${Math.round(val)}/100`
    }
  }
}
```

Clicking a polar chart slice triggers the same drill-down as clicking the corresponding metric card.

### Alerts Ticker (Bottom Strip)

- Height: 36px, fixed at bottom of RiskRadarView content (NOT position:fixed — scrolls with page)
- Background: `--rr-critical` at 15% opacity with 1px top border in `--rr-critical`
- Content: computed list of critical items — "⚠ {metric}: {human-readable description}" — separated by ` · `
- Scrolls horizontally via CSS marquee-style animation when content > viewport width
- Clickable items: same drill-down as card click
- Hidden when no items are in WARN/HIGH/CRITICAL range (score < 40 across all metrics)
- In light mode: background uses `--rr-high` at 8% opacity (softer, less aggressive)

### Manual Refresh

Refresh button (`mdi-refresh`, variant="tonal", color="primary") in header: re-runs `useRiskScores()` fetch sequence. Shows `loading` spinner during fetch. No auto-refresh in MVP.

### Subsidy / Year Filter

Identical behavior to DashboardView.vue:
- Year chip group (mandatory, single select) — `selectedYear` ref
- Subsidy multi-select `v-select` — `selectedSubsidyIds` ref
- Quick subsidy chips bar below header (same pattern, same CSS classes: `.subsidy-chips-bar`, `.subsidy-chip`)
- Changing either filter triggers `useRiskScores()` re-computation

## Accessibility

### Keyboard Navigation

- Toggle chips: focusable with Tab, activated with Space/Enter
