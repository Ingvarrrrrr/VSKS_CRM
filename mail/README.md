# gala-mail — отправка писем восстановления пароля / подтверждения email с домена galaa.ru

Контейнер отправляет почту ТОЛЬКО наружу (Postfix + подпись DKIM), входящую почту не принимает
и не слушает снаружи — порт 25 есть только внутри docker-сети этого проекта
(`docker-compose.yml`, сервис `mail`, без `ports:`). По образцу FOODSIZO
(`server/mail-relay/`), адаптировано под домен `galaa.ru` / селектор `gala`.

Этот файл — что владельцу нужно сделать руками: DNS-записи и проверки в панели Timeweb.

## 1. DNS-записи для домена galaa.ru

Зайти в панель управления DNS для домена `galaa.ru` (там же, где заведены остальные записи
сайта).

### A-запись (адрес почтового сервера)
```
Тип:  A
Имя:  mail
Значение: 201.34.139.168
TTL:  по умолчанию
```
Это даёт `mail.galaa.ru` → сервер, на котором крутится весь стек GALA.

### TXT-запись SPF (кто имеет право слать письма от имени домена)
```
Тип:  TXT
Имя:  @  (то есть сам galaa.ru)
Значение: v=spf1 ip4:201.34.139.168 ip4:201.34.140.226 -all
```
Если у домена уже есть SPF-запись (например, под другой сервис) — не заменять, а ДОПОЛНИТЬ
один список `ip4:`/`include:` внутри ОДНОЙ записи (две TXT-записи SPF на одном домене не
работают, почтовые серверы читают только первую).

### TXT-запись DKIM (подпись писем — ключ выпускает сам контейнер)
```
Тип:  TXT
Имя:  gala._domainkey
Значение: <взять из лога контейнера, см. ниже>
```
Как получить значение: после первого запуска контейнера `mail` —
```
docker logs vsks-crm-mail-1 | grep -A5 "TXT-запись"
```
(имя контейнера может отличаться — посмотреть `docker ps | grep mail`). В логе будет строка
вида `gala._domainkey IN TXT ( "v=DKIM1; h=sha256; k=rsa; p=ОЧЕНЬ-ДЛИННАЯ-СТРОКА" )` — в поле
«Значение» записи нужно вставить ровно то, что внутри кавычек после `p=` и до конца, включая
`v=DKIM1; h=sha256; k=rsa; p=...` целиком, без внешних кавычек. Если панель DNS режет длинные
TXT на части по 255 символов — она сама склеит их при показе домену, просто вставляйте текст
как один блок в поле значения.

### TXT-запись DMARC (политика: что делать с письмами, не прошедшими SPF/DKIM)
```
Тип:  TXT
Имя:  _dmarc
Значение: v=DMARC1; p=quarantine; rua=mailto:ЗАМЕНИТЕ-НА-СВОЙ-EMAIL@galaa.ru
```
`rua=mailto:...` — куда присылать агрегированные отчёты о попытках подделки писем от вашего
домена; замените на почту, которую вы реально проверяете. `p=quarantine` — подозрительные
письма уходят в спам, не отбрасываются молча; можно позже ужесточить до `p=reject`, когда
убедитесь, что легитимные письма доходят.

## 2. Панель Timeweb Cloud

### PTR-запись (обратная DNS, адрес → имя)
Панель Timeweb Cloud → Облачные серверы → сервер 201.34.139.168 → вкладка «Сеть» (или
«IP-адреса») → рядом с публичным IP — пункт «PTR-запись» / «Обратная зона». Установить:
```
201.34.139.168 → mail.galaa.ru
```

⚠️ **Важно про общий IP с другими проектами:** на этом же IP (201.34.139.168) может работать
почтовый релей другого проекта (например, FOODSIZO/sizo-mail). PTR — ОДИН на весь IP, его
нельзя завести по-разному для разных доменов. Если FOODSIZO включит свой relay с того же IP,
его исходящие письма тоже будут представляться HELO `mail.galaa.ru` (так настроен main.cf
второго проекта) — это нормально и не ломает ничего: PTR/HELO общие для IP, а SPF и DKIM —
отдельные у каждого домена (SPF galaa.ru и SPF sizoperedacha.ru оба перечисляют этот IP как
разрешённый отправитель; DKIM подписывается селектором и доменом, который реально стоит в
заголовке `From`, так что подмены писем это не создаёт).

### Исходящий порт 25
У Timeweb на этом сервере порт 25 исходящий уже открыт (проверено ранее, тикет в поддержку
не требуется). Если на каком-то другом сервере будете разворачивать то же самое — проверить
командой с сервера:
```
nc -vz -w5 smtp.gmail.com 25 || echo "порт 25 закрыт исходящий"
```

## 3. Проверка доставки

После того как DNS-записи выше разошлись (обычно от 15 минут до нескольких часов):
1. Зайти на https://www.mail-tester.com — сайт даст одноразовый адрес вида `test-xxxx@mail-tester.com`.
2. Вызвать `send_password_reset_email`/`send_verification_email` (`backend/app/utils/email.py`)
   на этот адрес — например, через реальный сценарий «забыли пароль» на проде с этим адресом
   в поле email, либо коротким скриптом с прямым вызовом функции.
3. Вернуться на mail-tester.com и посмотреть оценку — там же видно, прошли ли SPF/DKIM/DMARC,
   и конкретная причина, если что-то не так.
4. Дополнительно — отправить реальное письмо на свой ящик на Яндексе/Gmail и проверить, что
   оно не попало в «Спам».

## 4. Включение на проде (.env, вне git)

```
EMAIL_MODE=relay
SMTP_HOST=mail
SMTP_PORT=25
SMTP_USER=
SMTP_PASSWORD=
SMTP_FROM=noreply@galaa.ru
```
`SMTP_USER`/`SMTP_PASSWORD` оставить пустыми — relay-режим не требует логина (сеть docker уже
ограничивает, кто может отправлять, см. `mail/main.cf`: `mynetworks`). Если что-то пойдёт не
так с relay и нужно временно вернуться на прежний режим через Яндекс — просто убрать
`EMAIL_MODE` (или поставить `EMAIL_MODE=login`) и вернуть `SMTP_HOST=smtp.yandex.ru`,
`SMTP_USER`/`SMTP_PASSWORD` как было.

## Технические детали (для разработчика, не для владельца)

- Домен и селектор зашиты в `opendkim.conf` (`Domain galaa.ru`, `Selector gala`) и в
  `entrypoint.sh`. Менять домен/селектор означает новую DKIM-пару и новую TXT-запись.
- Ключ хранится в named volume `mail-dkim` (см. `docker-compose.yml`) — переживает
  пересоздание контейнера. Удаление volume = новый ключ = обязательно обновить TXT в DNS.
- Порт 25 контейнера НЕ опубликован (`docker-compose.yml`: сервис `mail` без `ports:`) —
  достижим только из сети этого compose-проекта (правило №4 CLAUDE.md: наружу только
  80/443+22).
- `main.cf`/`entrypoint.sh` отклоняют отправителя (envelope-from) вне домена `galaa.ru` —
  это не open relay: даже код внутри docker-сети не сможет отправить письмо с чужим `From`
  через этот контейнер.
