# Phase 27.1 Plan 01: ContractItem Model + Schema + Migration Foundation Summary

**One-liner:** SQLAlchemy ContractItem model with CASCADE/SET NULL FKs, check_schema.py idempotent CREATE TABLE + backfill SQL for legacy contracted purchases, and Pydantic ContractItemOut/Create/Update schemas.

## What Was Built

### Task 1: ContractItem ORM Model + Schemas

**`backend/app/models/contract_item.py`** (new) — ContractItem SQLAlchemy model:
- `purchase_id` FK → purchases.id ON DELETE CASCADE (NOT NULL)
- `source_item_id` FK → purchase_items.id ON DELETE SET NULL (nullable — reshape support D-05)
- `contract_id` FK → contracts.id ON DELETE SET NULL (nullable — CD-2)
- `product_id` FK → products.id ON DELETE SET NULL (nullable — CD-1)
- `name TEXT NOT NULL`, `quantity NUMERIC(15,4)`, `unit VARCHAR(50)`, `unit_price/total NUMERIC(15,2)`
- `match_confirmed BOOLEAN NOT NULL DEFAULT TRUE` (Phase 21 pattern)
- `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`, `updated_at TIMESTAMPTZ` (auto onupdate)
- Relationships: `purchase` (back_populates), `source_item`, `product`, `contract`

**`backend/app/models/__init__.py`** — ContractItem registered in Base.metadata via import.

**`backend/app/models/purchase.py`** — `contract_items` relationship added with `cascade="all, delete-orphan"` and `lazy="selectin"`.

**`backend/app/schemas/schemas.py`** — 4 new Pydantic classes:
- `ContractItemBase` — shared fields with all optional except `name`
- `ContractItemCreate(ContractItemBase)` — for POST body
- `ContractItemUpdate(BaseModel)` — all fields optional, for PATCH body
- `ContractItemOut(ContractItemBase)` — adds `id`, `purchase_id`, `created_at`, `updated_at` + `from_attributes=True`

**`backend/tests/conftest.py`** — 4 new fixtures:
- `make_purchase` — factory creating minimal Purchase
- `make_purchase_with_items` — factory creating Purchase with N PurchaseItems
- `make_contract_item` — factory creating ContractItem with sane defaults
- `make_legacy_contracted_purchase` — factory for backfill testing (contracted status, no contract_items)

**`backend/tests/test_contract_item_model.py`** — 5 Wave 0 model tests:
- `test_create_contract_item` — creation + match_confirmed=True default
- `test_source_item_id_nullable` — all optional FKs can be NULL
- `test_cascade_delete_on_purchase` — purchase deletion cascades to contract_items
- `test_set_null_on_source_item_delete` — purchase_item deletion sets source_item_id=NULL
- `test_purchase_relationship_has_contract_items` — Purchase.contract_items relationship works

### Task 2: check_schema Migration + Lifespan + Backfill Tests

**`backend/check_schema.py`** — 2 new functions:
- `_ensure_contract_items_table(conn)` — idempotent CREATE TABLE IF NOT EXISTS for all 13 columns + CREATE INDEX IF NOT EXISTS for purchase_id. Two separate execute() calls (asyncpg Pitfall 2).
- `_backfill_contract_items_from_purchase_items(conn)` — Step 1: INSERT with NOT EXISTS guard for all purchases in contracted/ordered/delivered/paid. Step 2: UPDATE purchases.contract_price = SUM(ci.total) for non-framework-head only (D-07 exclusion).

**`backend/app/__init__.py`** — lifespan startup block:
```python
from check_schema import _ensure_contract_items_table, _backfill_contract_items_from_purchase_items
async with engine.begin() as conn:
    await _ensure_contract_items_table(conn)
    backfilled = await _backfill_contract_items_from_purchase_items(conn)
# non-fatal: wrapped in try/except
```

**`backend/tests/test_contract_items_backfill.py`** — 5 Wave 0 backfill tests:
- `test_legacy_purchases_get_contract_items` — 2 purchase_items → 2 contract_items after backfill
- `test_backfill_idempotent` — second run does not duplicate (NOT EXISTS guard)
- `test_backfill_recomputes_contract_price` — contract_price recalculated for single type
- `test_backfill_skips_framework_head` — framework_cumulative head keeps manual price
- `test_backfill_skips_non_contracted` — planned status gets 0 contract_items
