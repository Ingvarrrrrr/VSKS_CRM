# План реализации CRM системы для управления договорами и подрядчиками

## Анализ требований

### Основные функции системы:

1. **Управление контрагентами**
   - Внесение данных о контрагентах (вручную, из Word/PDF, из таблицы)
   - Автозаполнение реквизитов при выборе контрагента
   - Хранение полных реквизитов (ИНН, КПП, банковские реквизиты и т.д.)

2. **Управление договорами**
   - Создание договоров с составом (товары/услуги)
   - Управление статусами (плановый, подтвержденный, ведутся работы)
   - Отслеживание стадий исполнения
   - Плановые даты поставки/исполнения
   - Связь с контрагентами

3. **Управление закупками**
   - Создание закупок
   - Статусы: плановый, подтвержденный, ведутся работы
   - Связь с договорами

4. **Формирование документов**
   - Лист согласования (автозаполнение)
   - Договоры (на основе шаблонов)
   - Служебные записки на закупку
   - Служебные записки на оплату

5. **Управление платежами**
   - Загрузка данных о платежах из Excel
   - Автоматическая сверка с договорами
   - Отметка оплаченных договоров

6. **Категоризация по ФЭО**
   - Направление расходов по категориям ФЭО
   - Тип расходов в соответствии с ФЭО
   - Направление расходов из приложений к ФЭО
   - Конкретизированный тип расходов
   - Зависимости между категориями (формулы)

7. **Дашборд и отчетность**
   - Интерактивный дашборд по субсидиям
   - Метрики: Общий объём субсидии, Законтрактовано, Планируется к контрактации, Поставлено, Оплачено
   - Графики разбивки по товарам/услугам
   - Реестр заключённых договоров
   - Поиск договоров по контрагенту

8. **Многопользовательская работа**
   - Интеграция с Google Sheets
   - Одновременное внесение данных разными пользователями
   - Синхронизация данных

## Архитектурные решения

### Вариант 1: Google Apps Script + Google Sheets (Рекомендуется)

**Преимущества:**
- ✅ Уже есть начальный код на Google Apps Script
- ✅ Бесплатная платформа для совместной работы
- ✅ Встроенная интеграция с Google Sheets
- ✅ Простое развертывание
- ✅ Возможность работы через веб-интерфейс

**Недостатки:**
- ⚠️ Ограничения по производительности
- ⚠️ Сложность работы с большими объемами данных
- ⚠️ Ограниченные возможности визуализации

**Структура:**
```
Google Sheets:
├── GoodsService (основная таблица)
├── Контрагенты_список
├── Категории_из_ФЭО
├── Категории_из_приложения
├── Дашборд
└── Реестр_договоров

Google Apps Script:
├── Code.gs (основная логика)
├── ContractDialog.html (форма договора)
└── ContractorDialog.html (форма контрагента)
```

### Вариант 2: Веб-приложение на Node.js + PostgreSQL + Google Sheets API

**Преимущества:**
- ✅ Полный контроль над функциональностью
- ✅ Мощная база данных
- ✅ Современный UI/UX
- ✅ Лучшая производительность
- ✅ Расширяемость

**Недостатки:**
- ⚠️ Требует хостинг и сервер
- ⚠️ Более сложная разработка
- ⚠️ Необходимость настройки инфраструктуры

**Технологический стек:**
- Backend: Node.js + Express
- Database: PostgreSQL
- Frontend: React/Vue.js + табличный компонент (AG-Grid, Handsontable)
- Google Sheets API для синхронизации
- Документы: docx-templates или docxtemplater

### Вариант 3: n8n + Google Sheets + База данных

**Преимущества:**
- ✅ Визуальная настройка workflows
- ✅ Готовые интеграции
- ✅ Автоматизация процессов
- ✅ Не требует глубокого программирования

**Недостатки:**
- ⚠️ Ограниченная кастомизация UI
- ⚠️ Сложность для сложной бизнес-логики
- ⚠️ Требует настройки workflows

**Применение n8n:**
- Автоматизация загрузки платежей
- Синхронизация данных между системами
- Автоматическое формирование отчетов
- Уведомления о статусах

## Структура базы данных (для будущей миграции)

```sql
-- Контрагенты
CREATE TABLE contractors (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    full_name TEXT,
    inn VARCHAR(20),
    kpp VARCHAR(20),
    director_name VARCHAR(255),
    director_position VARCHAR(255),
    acting_basis TEXT,
    account_number VARCHAR(50),
    correspondent_account VARCHAR(50),
    bik VARCHAR(20),
    legal_address TEXT,
    actual_address TEXT,
    org_phone VARCHAR(50),
    email VARCHAR(255),
    contact_person VARCHAR(255),
    contact_phone VARCHAR(50),
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Субсидии
CREATE TABLE subsidies (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    total_amount DECIMAL(15,2),
    year INTEGER,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Договоры
CREATE TABLE contracts (
    id SERIAL PRIMARY KEY,
    contract_number VARCHAR(100),
    subsidy_id INTEGER REFERENCES subsidies(id),
    contractor_id INTEGER REFERENCES contractors(id),
    purchase_number VARCHAR(100),
    order_number VARCHAR(100),
    subject TEXT,
    status VARCHAR(50), -- плановый, подтвержденный, ведутся работы
    execution_stage VARCHAR(100),
    planned_delivery_date DATE,
    total_amount DECIMAL(15,2),
    contracted_amount DECIMAL(15,2),
    delivered_amount DECIMAL(15,2),
    paid_amount DECIMAL(15,2),
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Состав договора (товары/услуги)
CREATE TABLE contract_items (
    id SERIAL PRIMARY KEY,
    contract_id INTEGER REFERENCES contracts(id),
    product_name TEXT,
    planned_quantity DECIMAL(15,2),
    unit VARCHAR(50),
    planned_cost_per_unit DECIMAL(15,2),
    final_price_per_unit DECIMAL(15,2),
    category_feo VARCHAR(255),
    type_feo VARCHAR(255),
    direction_feo VARCHAR(255),
    specific_type VARCHAR(255),
    created_at TIMESTAMP DEFAULT NOW()
);

-- Платежи
CREATE TABLE payments (
    id SERIAL PRIMARY KEY,
    contract_id INTEGER REFERENCES contracts(id),
    payment_date DATE,
    amount DECIMAL(15,2),
    payment_number VARCHAR(100),
    source_file VARCHAR(255),
    created_at TIMESTAMP DEFAULT NOW()
);

-- Закупки
CREATE TABLE purchases (
    id SERIAL PRIMARY KEY,
    purchase_number VARCHAR(100),
    subsidy_id INTEGER REFERENCES subsidies(id),
    status VARCHAR(50), -- плановый, подтвержденный, ведутся работы
    planned_date DATE,
    created_at TIMESTAMP DEFAULT NOW()
);
```
