# Multi-Agent Team Architecture & Guidelines (Antigravity)

Проект: **VSKS_CRM (GALA)**
Этот документ автоматически загружается средой Antigravity для всех сессий в данном проекте.

---

## 1. Роли и стек агентов

Вместо выполнения всей рутины на тяжелой дорогой LLM используется специализированная команда:

| Роль | Тип субагента | Рекомендуемая модель | Задачи |
|---|---|---|---|
| **Оркестратор / Архитектор** | Главный агент (`self`) | `pro` / `inherit` | Декомпозиция, общая архитектура, контроль бизнес-правил, синхронизация с Obsidian Vault (`Lessons.md`, `05_Gotchas.md`, `HANDOFF.md`), финальная приёмка и пуш. |
| **Быстрый разработчик** | `fast_coder` | `flash` / `flash_lite` | Рутинный бэкенд и фронтенд: CRUD эндпоинты FastAPI, верстка форм Vuetify 3, маппинг колонок Excel, типизация, юнит-тесты. Экономит токены, работает максимально быстро. |
| **Гейм-дизайнер / Разработчик игр** | `game_dev` | `flash` / `inherit` | Мини-игры: физика Canvas/DOM, игровой цикл, управление, анимации, звуки (Web Audio), Game Over экраны, подсчет очков и интеграция с таблицей рекордов `/api/games/{game}/score`. |
| **Тестировщик / Верификатор** | `verifier` | `flash` / `pro` | Проверка доработок по принципам `gala-accept`: проверка сценариев пользователя, отсутствие ошибок консоли / 422 / 500, проверка форматирования чисел, локализации, E2E тесты. |
| **Исследователь** | `research` (встроенный) | `inherit` / `flash` | Глубокий поиск по кодовой базе, документам и веб-источникам без загрязнения основного контекста. |

## 2. Принципы оркестрации

1. **Контекст Obsidian:**
   - Перед сложными архитектурными решениями и изменениями логики сверяться с `c:\Users\1\Documents\VAULT_for_LLM\Projects\VSKS_CRM\05_Gotchas.md` и `Lessons.md`.
   - В конце крупных этапов обновлять `HANDOFF.md` и добавлять запись в `Sessions/`.
2. **Делегирование рутины:**
   - Четко формулировать подзадачу для `fast_coder` с указанием конкретных файлов и требований.
   - Не гонять тяжелую модель на шаблонные правки.
3. **Безопасность дерева репозитория:**
   - В репозитории есть чужие незакоммиченные файлы — не трогать их, не добавлять через `git add .`.
   - Коммитить строго целевые измененные файлы.
4. **Релиз:**
   - Пуш на GitHub (`origin/claude`) выполнять строго по подтверждению пользователя («пуш»).
   - После пуша помнить, что на сервере запускается автодеплой.
